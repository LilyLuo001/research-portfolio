## 二、从现在到结束的具体步骤

### 第 1 步：把 W002 高组的未知状态收口

**问题：它真的没有足够分析师，还是原数据抽取遗漏？**

执行：

1. 检查已找到的 2019–2021 抽取 SQL、执行记录和行数对账。
2. 明确 `usfirm=1`、`measure=EPS` 等过滤是否与该候选的检索目标一致。
3. **如果旧执行日志不存在，不无限追日志。** 在许可和连接允许时，直接对这 4 个公告键做源端、四列元数据定向对账，检查证券标识、会计期和原 90 天日期窗口。
4. 不读取 EPS 或预测值，不重下整个 IBES 库。

输出：每个键属于“观察到 ≥2”“经核实不足 2”还是“明确缺哪项源数据”。

**停止条件：**如果完整检索后高组仍缺 PRE 或 POST 支持，该候选不能支撑当前比较；不能靠买报价救回来。

### 第 2 步：认证时钟，并处理会影响结论的未知人口

这两项可以并行，但不需要同时大规模运行。

**A. 时钟与 session**

- 核实公告时间字段的含义、时区、修订含义和精度。
- 使用历史交易日历，处理夏令时、提前收盘、非交易日和边界不确定性。
- 对已有不截断元数据重新分类：pre-open、RTH、after-close，以及真正满足 RTH-60 的记录。
- 时间不确定跨越边界的记录保持 UNKNOWN。
- Session 可分类，不等于五分钟端点精度合格。

**B. 人口缺口**

- 对 202 个未映射组合，以及尚未判定 competing-conversion 状态的候选，按具体缺口分组。
- 优先处理可能补上缺失高组、缺失波次的记录。
- 只补历史有效标识、公告元数据或竞争转换信息；不虚构完整股票×交易日面板。

输出：有依据的 session 表和候选缺口表。

**通过标准：**能够知道哪些比较单元实际存在，哪些缺失，哪些仍未知。不能再把目前的名义时钟、known-clean 子集当成完整总体上限。

### 第 3 步：确认真正的转换人口与处理时间

**问题：这些股票的暴露是否确实在转换消息之前形成？**

逐 package／fund 核实：

- 最早公开公告时间及不确定区间。
- 实施日期和包内基金关系。
- 公告前持仓、分母日期、split basis、必要的 ETF-class pro-rata 关系。
- 经济 sponsor，以及同期管理、mandate、费用、基准等变化。
- 其他 conversion 是否污染 PRE／POST 窗口。

保留经济日期与信息可得日期的区别。已验证部分复用，只补具体缺件。

输出：版本固定的 package、股票、暴露和排除名单。

**通过标准：**人口和 H/L 分组由批准的公告前规则确定，不能由分析师覆盖或报价好坏反向决定。

### 第 4 步：做一次“原设计还能不能成立”的早停判断

在已经认证的候选人口上，检查：

- 每个主波次是否都有 H/L × PRE/POST 支持。
- 分析师、session 和 competing-conversion 排除分别损失多少。
- 原合同要求的股票×共同 calendar-cell 是否有真实观察。
- 行业控制、时间控制所需信息是否可得。
- 支持是否实际上只来自一个股票、一个 package 或一个 sponsor。

输出：逐步损耗表、必要支持矩阵、明确不可估的单元。

**这里是最重要的分叉：**

| 结果 | 后续处理 |
|---|---|
| 原比较具备必要支持 | 进入测量和校准 |
| 缺少可补的明确输入 | 只补对应输入，再更新受影响单元 |
| 在已核实范围内原比较无法成立 | 停止该设计的报价购买与功效模拟，提交一次明确的设计修改决定 |

不能自动转非 RTH、把 W016 stress 升成主样本、降低分析师要求或删除控制变量来获得“通过”。

### 第 5 步：只为仍然有效的事件补齐行情

**到这里才决定哪些 Databento 数据真正值得买。**

执行：

1. 将冻结的合格事件与已有下载 manifest 对齐。
2. 复用已下载、证券类别和日期正确的数据。
3. 检查 stock／SPY 配对、历史证券标识、feed、schema 和窗口是否匹配。
4. CRD 类别修复、失败请求等，只处理仍影响有效事件的部分。
5. 缺什么买什么，但不重复购买已有 SPY 或整个面板。

输出：缺口订单、购买记录、下载完成状态。

**边界：**单市场报价仍按单市场解释，不能把四个 venue 自动叫作全国 NBBO。若研究必须测量全市场，先解决相应覆盖要求。

### 第 6 步：完成真实报价测量测试

先做小样本，再运行冻结清单：

- 解码文件，检查记录是否可用。
- 核对 stock／SPY 时间对齐。
- 测试 baseline、5／15／30／60 分钟、close、下一交易日 close。
- 区分有效但未变化的报价、stale 状态、withdrawal 和真正缺失。
- 检查 corporate actions、停牌、提前收盘和跨日处理。
- 输出每个 horizon 的可用性及六 horizon common mask。

至少 20 条最终小样本观察回查原始记录。涉及新实现的全量入口必须绑定对应代码、配置、输入 manifest 和通过记录。

**POST 只返回已许可的覆盖与资格标记，不开放响应值。**

输出：测量测试报告、逐阶段 coverage 和失败原因。

### 第 7 步：构建 PRE-only SUE 与校准输入

由受许可的 custodian 在 SCC 内运行：

- 检查 actual／forecast 的币种、share basis、会计期及版本一致性。
- 按冻结规则处理每位分析师的最后一次有效预测。
- 严格处理 release 前窗口和同日先后不明情况。
- 构建 PRE SUE、统一缩放、β 和 PRE response。
- 保留跨 horizon 协方差及事件复用关系。

“两位 analyst IDs”只是前面的检索条件，**这一阶段才判断是否真的有可用 SUE。**

输出：PRE 输入资格、校准汇总及 lineage；不使用 POST 响应校准。

### 第 8 步：验证真实设计矩阵与识别威胁

检查：

- 必需列的 rank、完全共线与不可估参数。
- 残差化后的关键 treatment×SUE 列是否还有信息。
- leverage 是否被少数股票／事件支配。
- 股票、事件、日期、package、经济 sponsor 的依赖。
- PRE-only 稳定性、placebo 和早晚 PRE 对比。
- 同期变化、选择性覆盖和 spillover 是否破坏解释。

不通过删控制来修复 rank；不把连接分量当有效样本量；不把 pretrend 不显著当作平行趋势证明。

输出：**哪些识别假设有证据支持、哪些只能假定、哪些与现有证据冲突。**

### 第 9 步：冻结推断方法和“足够”的标准

在正式功效运行前，集中解决科学选择，不逐条反复问：

- 最终人口、主 session、比较对象及 wave 权重。
- 少 sponsor／事件复用条件下可辩护的推断程序。
- 经济上有意义的效应幅度。
- 多重检验 family、terminal／shape 的解释范围。
- H3 是否仍纳入本 pilot 的完成标准。

若经济幅度尚未指定，可以先报告完整 MDE／power 曲线，但不能宣称“功效足够”。

若没有可辩护的推断程序，只能报告明确标注的模型条件精度，不能给 confirmatory GO。

### 第 10 步：先检验统计程序，再计算功效

顺序不能倒过来：

1. 在最终实现上运行受变更影响的合成测试。
2. 测试零效应下的拒绝率、置信区间覆盖率和失败拟合比例。
3. 检查事件重复是否制造虚假精度，跨 horizon 相关性是否保留。
4. 这些测试合格后，才运行功效情景。

功效情景包括：

- 不同效应大小。
- PRE→POST 方差变化。
- sponsor／日期依赖压力。
- 实际 coverage 与额外缺失。
- 增加同波次股票、增加 PRE 事件、增加独立 package 三类扩展。

每次模拟使用同一估计程序；失败重复不能悄悄删除。模拟生成的 POST 不等于观察到的 POST。

输出：校准依据、size／coverage、MDE、power 曲线、模拟不确定性及扩样价值。

### 第 11 步：一次独立科学复核，形成最终决定

到这时才使用 **Astra／high**，审查实际结果，而不是再审一份计划：

- 人口、估计对象和代码是否一致。
- 测量能否支撑研究主张。
- 识别假设与依赖处理是否可辩护。
- 功效是否来自真实信息，而非重复事件或乐观模拟。
- 哪项补数真正可能改变决定。

发现具体问题，只修并复核受影响部分，不重启全项目。

最终交付以下之一：

- **GO：**指定设计满足进入正式研究准备的条件。
- **HOLD_DATA：**明确一项可补输入及其预期决策作用。
- **HOLD_DESIGN：**需要改变研究对象、比较或推断。
- **NO_GO：**指定设计在已核实范围内不值得继续。

真实 POST headline effect 的估计仍是另外的解封阶段，**不是完成这次 pilot 可行性与功效判断的必要条件。**

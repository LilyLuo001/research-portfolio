# Daily nonmechanical and issuer-specific network specification

Frozen: 2026-09-21, before this stage reads any new return response. This amendment governs only the new daily-frequency development analysis. It does not alter the archived conversion project or unseal the Phase 3 minute-response validation set.

## Seal and exposure resolution

The Phase 3 contract said that six clock-qualified development events would be selected and that other eligible events would remain sealed. In execution, no six-event assignment was ever formed: `CLOCK_SUMMARY.json` reports zero scientifically frozen events, and the only response-bearing technical diagnostics used two Exxon dates (2023-01-31 and 2023-07-28). Accordingly, there is no named prior daily validation assignment to reuse. Those two dates are treated as exposed for any frequency.

For this new daily estimand, unique announcement dates in January--June 2023 are the development date block. July--December dates remain untouched holdout dates and are not read by the daily analysis. The exposed 2023-07-28 date remains excluded, not restored to holdout status. This deterministic date-block split was fixed without returns. A future confirmatory analysis must freeze its code and inference plan before reading the untouched dates.

The seal applies to every outcome window, not only focal events: an event or control candidate is ineligible if either of its two return dates is after 2023-06-30. No July--December return is read for this stage.

## Daily population and event mapping

The event calendar is the already constructed 32 top-eight issuer I/B/E/S release groups. Release groups sharing issuer and date collapse to one issuer-date. Dates whose two-session windows share a trading day belong to the same overlap block; this, not issuer-event rows, is the dependence unit. Because the source clock is not certified, every development event response is the compound CRSP company return across the announcement trading date and the next trading date. This conservative two-session window covers a release before the first close or after that close; it is not an immediate response and may include unrelated news.

Company returns aggregate all date-valid common share classes (SHRCD 10/11) using market capitalization observed on the prior trading day. Delisting returns are combined where available. A two-return window economically spans from the close before its first return date through the close on its second return date. With date-only news, announcement-overlap flags therefore use calendar dates strictly after the preceding trading date and through the second return date; this includes intervening weekends and holidays but cannot resolve within-day ordering. The broad daily-fact population is the fixed 2022-12-30 top-500 issuer roster. On an event date it excludes every top-eight announcer whose two-session event window overlaps the focal window (not merely same-date announcers), plus receiver companies with their own mapped I/B/E/S EPS announcement in that calendar span. Other top-eight firms remain in this broad population. The issuer-receiver network population is narrower: receiver ranks 9--500, because the frozen `private_pair_scores` table intentionally excludes every top-eight issuer as a receiver.

## Weights, controls and primary contrasts

Equal-weight and fixed 2022-12-30 company-market-cap-weight aggregates are both reported. Fixed weights are never updated with post-event values. Announcer exclusion is therefore a constituent exclusion, not an ETF-price subtraction.

For each event date, control windows use the same weekday at offsets -28, -21, -14, +14, +21 and +28 calendar days, mapped as exact trading dates, with the same two-session length. A candidate is dropped if its trading sessions overlap any top-eight announcement window or if the receiver has its own EPS announcement in the control window's preceding-close-to-second-close calendar span. Controls are selected without returns. The stock-level control is the mean across remaining candidate windows; at least two valid control windows are required. The event-minus-control signed contrast is compound event return minus mean compound control return. The primary unsigned contrast is absolute compound event return minus mean absolute compound control return. Raw absolute event return is secondary because it can proxy persistent volatility.

Before responses, three public macro-date families were source-locked in `public_macro_calendar.json`: CPI, Employment Situation and FOMC statements. A two-session outcome window is flagged when any named macro release calendar date lies strictly after the preceding trading date and through its second return date; thus a weekend before a Monday return and a holiday between trading closes (for example Good Friday) are retained. The pre-specified sensitivity excludes focal overlap blocks whose event window has such an overlap. Control-window macro overlap is flagged and disclosed but not selectively removed from the primary control mean. The calendar is explicitly incomplete (for example PCE and GDP are absent), so neither main nor sensitivity results are called macro-clean. Event/date leave-one-out results and date-block dependence are reported; this 2023 development analysis is descriptive, not causal.

## Issuer-specific connection

The treatment proxy is the frozen 2022-12-30 PURE_D issuer-receiver `pair_strength`: the sum across eligible pooled ETF portfolio-reports of issuer reported weight times receiver reported weight. The contributing holdings reports can be stale relative to 2022-12-30; this is a cutoff-defined baseline network, not point-in-time ownership on every 2023 event date. It is unitless reported-weight coholding, not dollars, flows, trading, ownership, or a causal treatment. The stored pair table contains positive observed pairs only; a missing issuer-receiver row is UNKNOWN rather than a zero connection and is not imputed. For a date with multiple announcing issuers, the main row remains issuer-receiver, so a receiver/date response can repeat; inference and counts therefore treat overlapping-window date blocks as the dependence units. A secondary date-bundle exposure is the sum of observed pair strengths to all announcers that date, without imputing absent pairs to zero.

The frozen primary network outcome is the stock-level unsigned event-minus-control contrast. Secondary outcomes are signed event-minus-control and raw absolute event return. Specifications are: (1) connection only with event fixed effects; (2) plus pre-event log market cap, December-2022 log dollar volume, and focal issuer--receiver same SIC2; (3) within focal same-SIC2 support when rank and variation permit. Continuous connection is primary. No HIGH/LOW technical-sample result is a scientific estimator.

OLS point estimates use within-event demeaned variables. Log pair strength is standardized once over the eligible primary issuer-receiver analysis rows; coefficients are per one sample standard deviation of that log measure, and the scale is reported. Uncertainty is reported using an overlapping-window-block pairs bootstrap when at least six blocks contribute; with fewer than six blocks it is marked not reliably estimable. Six blocks only activates a heuristic interval and does not make it reliable. Because the event count is small, intervals are descriptive and leave-one-block estimates are mandatory. No p-value, causal identification, confirmatory power pass, or concentration-trend claim follows from these estimates.

## Stop rules and output boundary

One logical fixture and a small row-limited pilot must pass before one targeted full development run. Licensed identifiers, security rows, returns and full pair scores remain on SCC. Git-safe outputs contain only aggregate counts, coefficients, intervals, attrition, source hashes and bounded diagnostics. If required source fields, date-valid identity, own-announcement filtering, or at least two controls cannot be established, the affected estimand is reported as blocked rather than silently weakened.

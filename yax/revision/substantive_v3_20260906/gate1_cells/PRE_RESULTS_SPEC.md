# Gate 1 aggregate-cell build: pre-result contract

This directory specifies the only permitted construction of the aggregate
input to the V3 numerical-existence audit. It was written without running the
protected inputs. The production program must fail before publishing anything
unless the stamped canonical V2 contract, raw extracts, repository inputs,
authorization receipt, fixed membership, builder, authenticated runtime, and
committed clean-worktree contract match their SHA-256 locks.

The scientific object is a balanced 468-occupation by 114-observed-month
panel. Each row contains weighted employed-person stocks for ages 22--25 and
26--65. `WTFINL` enters once. For 2017--2019, `bridge_weight` allocates that
already survey-weighted stock across Census-2018 destinations; it is not a
second survey weight. The program independently reconstructs the grouped sums
and requires an exact zero gap.

The receipt separately counts integer physical rows and eligible source
records by extract. It then reconciles eligible records into invalid and valid
occupation records, valid records into early and current records, and early
records into matched and unmatched records. Matched early records expand into
explicit bridge descendants; the receipt counts unit-, zero-, and
strictly-fractional-weight contributions separately. Current records contribute
one direct row each. Per-source and total assertions link those contribution
rows to the final aggregated cells, while separate weighted-stock identities
verify route-mass conservation. Bridge descendants and aggregate rows are not
reported as respondent counts.

The production program implements a minimal target router locally. It reads
only `YEAR`, `MONTH`, `AGE`, `EMPSTAT`, `OCC`, and `WTFINL`, filters to the
canonical ages 22--65 at source, and explicitly replaces primary-extract March
rows in 2017--2021 with the March Basic repair extract before eligibility
filtering. The inherited general-purpose route was rejected after review:
`OCC2010` and `IND1990` feed stable-code and industry outputs that Gate 1 does
not retain, while importing that helper brought an incomplete and opaque
transitive runtime closure. Historical files remain byte-locked provenance,
not runtime dependencies. The synthetic parity test AST-loads only the three
exact historical helper functions and their constants from the byte-locked
file into a controlled namespace; it does not execute the historical module's
dynamic import closure. That test requires the new six-field target output to
equal the inherited target output after restricting it to ages 22--65.

Treatment classification is fixed, not learned from the postperiod. A fresh
2017-01--2022-11 reconstruction must reproduce the canonical 468-occupation
support, beta-quintile assignments, beta cutoffs, and Webb normalization. Only
after those checks pass does the builder attach the hash-locked membership's
fixed `beta_quintile` and `webb_z`. SOC2 `family` comes from the authenticated
computerization mapping. A SHA-256 fingerprint binds every exact
`(occ_code,family,beta_quintile,webb_z)` assignment.

The output retains December 2022 and genuine zero-total cells, while October
2025 remains absent. The expected grid has 53,352 unique rows.

Protected aggregate cells and their receipt are never repository outputs. The
caller must supply a nonexistent leaf outside the Git worktree, whose parent
already exists. Files are completed in a private staging directory and the
whole directory is renamed atomically. A failure removes only that newly
created staging directory and never overwrites an existing leaf.

Execution is permitted only in the declared CPython 3.13.8 SCC environment,
including the exact compiler, x86-64 architecture, glibc version, and package
versions recorded in `CELL_BUILD_SPEC.json`. The compute-node kernel release
is recorded but its patch level is nonbinding. The invocation is persisted as
one sanitized placeholder-only command template. The builder also requires a
Git HEAD descending from the declared ancestor, a completely clean worktree,
and byte identity between the live builder/spec/environment files and their
committed blobs. The receipt authenticates all of these facts for the numerical
consumer.

The builder does not read the historical sealed preperiod-cell artifact. It
does not fit a model, inspect a coefficient, tune a rule, or commit any
protected aggregate.

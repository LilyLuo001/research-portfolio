# 招聘要求候选抽取：标注与验收协议 v1

本轮产物是用于校准测量的候选证据，不是已经验证的岗位要求变量。来源是按文件随机化顺序选择、再按首次观察时期和时间风险分层的区域试样。昆山/乌镇本身按搬运分片组成，不能当作随机地域样本。

## 研究变量

1. **软件/工具**：实体和功能组分开；Office/表格、编程、数据分析、企业系统、协作工具分别保留。出现名称不自动等于要求掌握。
2. **经验**：总经验、相关/职业/行业/工具经验分开；保留下限/上限、至少/范围/优先、明确无需经验。多个经验条款不相加；senior/junior不是年限。
3. **学历**：学位层次、必备/优先、同等经验、替代资格路径分别保留。未提及不等于无需学历。
4. **任务**：编程、撰写、分析、协调、客户互动的职责证据，仅为有限词典候选，不能穷尽O*NET任务或构成任务复杂度指数。
5. **AI**：工具或技术提及、职责、资格和宣传语分别处理；不是雇主采用率、AI暴露度或AI替代指标。

每个候选保存 source file/row、原文、规范化文本证据段和其偏移坐标系。原文不可覆盖。正文版本日期仍标 unknown。

## 标注表

按单条广告分别填写：

- text_usable：是/否/不确定，语言由人工确认；脚本提示不当作英语分类。
- context：required / preferred / duties / company / benefits / ambiguous。
- tool_entity、tool_category、is_applicant_requirement；需区分广告在描述公司产品还是招聘条件。
- experience_scope、min_years、max_years、bound_type、no_experience_explicit。
- degree_level、required_or_preferred、equivalent_experience、alternative_path_text。
- task_family、is_actual_duty。
- extractor_false_positive、missed_requirement、reason。

即使程序没有候选也必须阅读原文寻找漏报，否则不能估召回率。富集的稀有/复杂例子另标 challenge_set，不与概率样本混算流行率。

## 开发与冻结验证

先建立约400条开发标注，再约800条独立冻结验证（若当前样本不足，报告实际样本量）。不能按行随机分割重复模板：至少以规范化文本指纹分组；验证另加企业留出和分时期误差检查。不同地区重复JOB_HASH/文本模板不得跨开发和验证泄漏。需要人工标注和独立复核；自动规则或另一模型标签不冒充人工金标准。

初始目标：拟进入主要结果的明确要求分类precision>=95%、recall>=90%，同时报告每时期样本数、置信区间、未知/失败率。复杂替代路径和年限区间单列严格匹配率；不达标就保留候选或缩小指标范围。

## 时间含义

CREATED只是首次观察广告时间，不是当前正文版本日期。跨季度/年/2022-11-30/2023-01-01分别保留风险标记。排除跨期广告是选择样本的敏感性分析，不能证明余下正文一定属于首次观察期。版本语义未核实前，按cohort输出的是样本和质量诊断，不能发布为当时招聘要求的因果时间变化。

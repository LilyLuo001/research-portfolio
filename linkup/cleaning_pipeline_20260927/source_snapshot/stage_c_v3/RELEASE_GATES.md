# 阶段 C v3：从基础清洗到研究变量

本轮目标是把招聘原文转换成可核查的条件证据，不把下载完成、匹配成功或零程序错误等同于研究变量验收。

## 可继续使用的已有成果

- 原始文件完整性、两区分片分工和副本去重已有核验结果；不重复扫描文件哈希。
- Records 的美国广告数量、首次观察月份、生命周期和 BASE_HASH 多地点分组可以独立于正文解析推进。
- O*NET 的 JOB_HASH 唯一性已验证，可用于一对一连接；非空码和格式通过仍不等于分类版本及经济含义已核验。
- Description 紧凑匹配保存来源及质量信息，不等于已经生成正式经验、学历或技术变量。

## 本轮输出及其用途

1. 固定 2,926 条试样重新提取，逐条保存代码版本、原文指纹、证据坐标、失败与截断标记。
2. 同一试样在昆山和乌镇运行同一代码，比对逐条标准化 JSON 的 SHA256。这验证实现可复现，不验证经济测量正确。
3. 输出广告状态、条件证据和资格关系候选三张窄表。未提及、明确无需、明确条件、语境不明、解析失败分别保留。
4. 美国 120 条开发复核包按既有 cohort 分层，并按规范化正文模板去重，排除已知开发案例。该包不是全国样本，也尚不是独立人工金标准。

普通经验、同职业/任务经验、行业/领域经验和工具经验是计划中的共同经济维度。解析器没有可靠识别的维度保留 unknown；不能仅用职业标题或软件关键词补齐。完整 AND/OR 资格路径尚未实现时，保存局部原文和 unresolved，不生成一个看似精确的最低学历或最低总年限。

`positive` / `is_applicant_requirement` 是程序候选诊断口径，可能同时包括 required 和 preferred，不可直接命名为“必备要求比例”。V4 另保留 qualification_expected（期待资格但强制程度不明）、context_conflict 和 qualification_relation_unresolved；研究表应按证据强度与路径状态分别汇总，不能把这些合并为一个二元必备标签。

## 全量候选提取与正式研究变量分开验收

- 固定试样回归、证据定位、跨区一致性和独立阅读复核完成后，才决定是否扩大候选提取；发现系统性错误必须先修复或缩小输出范围。
- 扩量后的候选仍需分时期、职业和正负例校准，报告样本选择与误差。规则测试通过或另一模型同意不能替代准确率证据。
- 经验年限不得跨条款相加；高中同等学历不得编码为工作经验替代；条件内部 AND 与条件之间 OR 不得混合。
- 研究汇总必须保留所有基准广告分母，分别记录无正文、无职业码、正文不足及无法判断；不能只保留成功识别要求的广告。

## 时间解释边界

正文历史版本语义仍未确认。当前文本按首次观察队列汇总时必须使用这一名称；不得称为当年实时招聘要求。短生命周期或同季度广告可作敏感性样本，不能作为时间真实性证明。

remote 的 START_DATE 高度集中在 2024 年以后，不回填 2022 年前状态；一键多行不能未经时间规则直接连接。独立的事前职业可远程性可以另行准备，但它表示任务可行性，不能等同实际远程工作采用。

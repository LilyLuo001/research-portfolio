# LinkUp Descriptions：研究导向的清洗与抽取方案

2026-09-25 修订。本文细化并覆盖原计划阶段 B 的执行口径；不是全量处理完成报告。

后续用户授权更新：现在开始“昆山已有数据连接审计 + 华中完整文件增量基础处理”，不等待全部下载。此前暂停的是盲目全量索引扩跑，不是禁止有明确交付的连接工作。执行以本文件末尾第 11 节为准。

## 1. 先纠正当前产出的定位

当前 `pilot_descriptions.py` 生成的是结构索引和质量诊断，不是可直接研究招聘要求的清洗数据。单分片输入 264,667,063 字节（约 252.41 MiB），121,451 行；输出 11,663,218 字节（约 11.66 MB / 11.12 MiB），行数守恒。两种单位不能混用来解释压缩率。

实际输出列为 JOB_HASH、SOURCE_FILE、SOURCE_ROW、TEXT_STATE、RAW_UTF8_BYTES、NORMALIZED_UTF8_BYTES、RAW_SHA256、NORMALIZED_SHA256、SCRIPT_HINT。原始 DESCRIPTION 未复制到输出，原始 Parquet 保留不变。因此输出小，主要是因为正文没有写入，不是正文被无损压缩至原来的约 4%。

代码目前对文字做 NFKC、HTML 实体解码、空白折叠后计算文本哈希；它保留 HTML 标签。SCRIPT_HINT 只查看前 4096 个字符的若干文字系统，不是语言识别。它没有提取软件技能、任务、学历、经验年限，也没有分离 required/preferred 或连接广告日期。

pilot 有 121,450 行 nonempty、1 行 normalizes-empty；112,047 个规范化文本哈希，9,404 个超过每哈希首行的重复行；该分片没有重复 JOB_HASH。它不是随机样本，这些数不能外推全库。文本相同也不证明广告、职位或招聘机会重复。

处置：保留已有索引和原文件；不把索引任务标成“阶段 B 完成”。停止自动扩展全库索引，允许已提交的 20 分片有限批次结束。华中增量索引程序尚未部署，继续暂缓；下载不受影响。后续根据研究抽取需要合并扫描步骤，避免先读全库算哈希，再为每个变量分别重读全部正文。

## 2. 研究对象决定清洗对象

工作问题仍是：相对于传统软件化，生成式 AI 扩散期的招聘调整体现在哪些工作内容、明确工具要求和既有经验要求上？区分岗位组成变化与可比工作内要求变化，再用 Revelio 工作史观察实际进入者。

不预设 AI 均等化、经验门槛提高或学历门槛下降。数据应同时容许这些方向、不变化以及不同职业方向不同。

| 要回答的层次 | 数据对象 | 应输出什么 | 不能替代什么 |
|---|---|---|---|
| 哪些工作被发布出来 | Job Records 广告记录、公司、角色、地区、时间 | 首次观察广告数及其分布、来源覆盖 | 广告数不等于招聘人数 |
| 工作在做什么 | Description 的职责、任务段落 | 工作活动与任务类别，保留证据 | 软件名称不等于任务内容或任务难度 |
| 招什么样的人 | Description 的任职资格、要求段落 | 软件技能、学历、既有经验的独立指标及其组合 | 要求不等于实际录用者能力或雇主偏好 |
| 最终谁进入这些工作 | 后续 Revelio 的事前工作史 | 新入职者既有经历分布 | 年龄不等于经验；简历技能不等于当年技能 |
| 与计算机化有什么共同和不同 | 独立的历史就业/任务测量与当前招聘证据 | 分开报告可比的结果与历史参照 | 2016—2019 不是计算机革命处理期 |

第一轮正文抽取以“软件/数字工具要求 × 既有经验要求”为核心，学历作为另一独立维度，任务内容作为解释这些变化不可少的测量层。初轮采用有限且可验证的任务类别，不做覆盖所有潜在软技能的庞大词典。AI 名称出现率另列，不能代替外部 AI 暴露指标或实际采用率。

历史计算机化的就业和工资结构比较依靠更早 CPS/Census/任务数据另行设计。当前 LinkUp 文本能测前后期招聘要求，不能重建 1980—2000 年代的招聘要求。没有统一历史测量时，不声称完成了两次革命的对称因果比较。

## 3. 第一关：文本的时间归属

实际 Description schema 只有 COMPANY_ID、COMPANY_NAME、DESCRIPTION、JOB_HASH，没有文本版本时间戳。Job Records 有 CREATED、LAST_UPDATED、LAST_CHECKED、DELETE_DATE，但不能仅凭字段名把任何一个当成正文生效日期。

阶段 A 已报告 LAST_UPDATED 315,238,346 行为空、41,210,868 行非空。空值不能证明从未修改；非空也需要核实是否只在正文变化时更新。这不是重新做阶段 A，而是把其结果应用到新连接层。

官方 [RAW 字典](https://data.support.linkup.com/kb/article/56-data-dictionary-raw-data-package-feeds/?section_id=7) 将 LAST_UPDATED 定义为最近观察到广告发生变化的抓取时间，未限定为正文变化；Description 只说明是抓取的完整正文及其连接键。公开定义尚未确认它是首次文本、末次文本还是历史版本。当前应称为“该快照中的无独立时间戳正文值”；每键基数仍需全局审计。

必须核实：

1. 当前快照每个 JOB_HASH 的 DESCRIPTION 是首次、末次、某次观测文本，还是多个版本？文件分片序号不是时间。
2. 正文修改是否覆盖旧文本？URL 被重复使用时 JOB_HASH 与 CREATED 如何处理？广告撤下再出现如何记录？
3. LAST_UPDATED 是标题/地点/任意字段变化，还是正文变化？空值的定义是什么？已关闭广告的文本是否冻结？
4. 是否可获取带版本日期的历史增量或字典说明？供应商修订是否回写历史？

按 JOB_HASH 审计 Description 全局键重复、原文冲突、跨公司冲突；不能依据单个分片唯一就推断全库唯一。对同一广告的多份不同文本，保留版本候选，不按文件顺序擅自选“最新”。

例如，一个首次观察于 2019 年但后来改写的广告，不能自动把当前正文视为其 2019 年招聘要求。是否实际存在这种错配需审计，不能先断言有或没有。

可行分支：若文档确认首次文本，用首次观察期；若为末次文本且能确认有效日期，按对应观察时间定义结果，改变估计对象并明确说明；若只能确认广告生命周期，探索生命周期完全落在同一分析期且正文冻结的受限样本，报告选择差异，不能把它当全样本。若版本无法定位，不发布按首次观察月份构建的“当时要求变化”结论。仍可推进正文抽取、连接诊断和时间含义明确的子样本。

## 4. 第二关：连接、分母与重复

沿用阶段 A 的 356,449,214 行全局唯一 JOB_HASH 广告骨架及 COUNTRY == USA 的主样本口径。Description 使用左连接审计，不能 inner join 后遗忘缺文本的广告。每个时间—企业—地区单元分别统计：广告总数、已到货文件覆盖、成功匹配文本、非空文本、语言可处理文本、抽取成功、明确要求、未提及、歧义/失败。

当前到货分片不是随机样本。区分“尚未下载”与“供应商无文本”；只有相关清单完整或可证明范围完整，才报告其最终文本覆盖率。2015、2016、2018 的供应商近似覆盖率不能替代本快照实际连接覆盖。

重复分四类，处置不同：

- 同一 JOB_HASH 的完全相同记录：记录来源后可以合并计算，但保存审计。
- 同一 JOB_HASH 的不同文本：版本/冲突对象，不直接删。
- 不同 JOB_HASH 的同文案：共享抽取缓存，保留广告行和统计权重。
- BASE_HASH 下的多地点/多次记录：沿用阶段 A 诊断，主结果按供应商广告记录；另做定义明确的地点折叠敏感性，不能宣称已识别真实 vacancy。

每次连接必须核对行数守恒、键 multiplicity、未匹配数和公司 ID 冲突。记录中的公司/地区与文本中的公司名冲突只标记，不自动用总部或正文覆盖职位地点。

## 5. 文本预处理服务于含义，不能只服务于更小文件

保留原始不可变 Parquet、文件校验值和 source row。规范化版本及抽取代码单独版本化。

解析 HTML 时保留段落、列表、标题顺序和必要边界；不能直接删除全部标签拼接字符串。实体解码、Unicode 规范化、大小写处理必须经过样例验证，特别是 C++、C#、.NET、R、SQL 等技术词及否定词、比较符号、数字范围。

分出职责、必备资格、优先资格、公司介绍、福利、平等就业等段落。公司模板可以在特征提取时排除或标记，但不得不留证据地从原文删除。句中混合必备和优先条件需要句级/从句级解析。

原哈希用于来源追溯，规范化哈希用于候选缓存；文本与标题/段落上下文共同影响判定时，缓存键必须包含相关上下文。纯文本相同但分类上下文不同不能盲目复用最终岗位标签。

保留原文证据片段或可重建的 source row + 原始字符/段落定位；规范化偏移量必须有映射，不能把规范化文本的偏移量冒充原文偏移量。语言检测另做经验证的轻量步骤；script hint 不能充当英语标签。

## 6. 抽取字典与不能合并的概念

| 模块 | 必要字段 | 易错点 |
|---|---|---|
| 软件/工具 | 工具实体、功能类别、required/preferred、熟练度描述、句子用途、证据 | 产品名出现在公司介绍不等于要求求职者掌握；使用 Excel 不等于编程 |
| 职责/任务 | 活动类别、对象、责任/执行/监督、来源段落 | 描述岗位做报告，与要求有报告经验是不同变量 |
| 经验 | 总工作/相关工作/职业/行业/工具经验；年限区间；required/preferred；零经验明确声明 | 多种经验可能重叠，不能相加；senior/junior 单列，不替代年限 |
| 学历 | 学位层次；required/preferred；等价经历；替代路径 | “本科或同等经验”不是无条件本科要求；未提及不是不要求 |
| AI 提及 | 工具/技术实体、招聘要求/职责/公司宣传/雇主采用陈述 | 广告声称使用 AI 不是独立验证的采用率 |

所有模块至少区分明确必备、明确优先、明确无需、未提及、歧义、处理失败。某些模块不适用“明确无需”时不强造标签；共同保留未知状态。

“本科 + 两年，或无本科 + 六年经验”用两条替代资格路径保存，不硬压为本科要求和六年经验。“至少三年相关经验，其中一年 Python”保存包含关系，不能计算成四年。十年公司历史、每周工作小时、薪资数字不能当经验年限。

工具功能类别与技术品牌名分开维护。冻结规则在各年份一致应用；新工具新增实体要有版本，并在所有时期重跑一致口径。AI 暴露、软件/常规任务暴露等解释变量应独立于本次要解释的招聘要求构建，避免把结果变化写进解释变量。

不把学历、软件、经验简单相加成“技能门槛指数”。某项明确要求消失仅表示广告不再明确陈述，不能直接解释为雇主降低实际录用标准。

## 7. 验证后再全量：分层样本与验收

先从完整 Job Records 骨架制定抽样计划，再在已到货文本中构造试样，记录未到货造成的偏差。不要用磁盘前 N 个分片当研究样本。

建议起步：约 400 条人工复核用于制定规则，另约 800 条冻结验证样本；按 2016—17、2018—19、2020—22、2023—完整最新月份、企业、角色、文本长度分层。2015 单列早期覆盖诊断。尚无可靠职业映射时用透明的标题族作抽样标签，不能冒充正式 SOC。

混合随机广告与故意富集的稀有/歧义广告，并记录抽样概率；富集样本只能测分类表现，不能直接估总体发生率。抽样按文本/企业模板分组拆分开发和验证集，避免相同文案泄漏；主要要求由两次独立复核和分歧裁决建立参考标签。自动模型复核不能冒充独立人工真值。

先验证各字段的精确率、召回率、混淆矩阵和未知率，特别检查跨时期误差差异。首轮建议明确要求标签精确率不低于 95%、召回率不低于 90% 作为迭代目标，同时报告样本量和不确定性；这不是统计学万能阈值，也不是达到后即可因果解释。年限区间/替代路径另报告严格结构一致率，失败不得只保留成功样本掩盖。

对不达标指标：修订规则或缩小可声明范围，保留 unknown，不强行给全库每行打标签。规则和验证方案冻结后才全量；全量阶段保留分时期/企业抽样复核。

## 8. 从广告级特征到研究面板

优先输出广告级特征与证据，不立即构造回归结论。正式职业面板以历史覆盖验证和冻结职业映射为前提。阶段 A 已确认 Job Records 无职业字段；后期供应商职业标签不能直接补全早年标签。

职业映射若使用模型，应优先依赖稳定标题/任务信息，避免让学历、经验或 AI 工具要求决定职业分类后又研究这些要求；固定分类体系，按年份验证。稳定标题/角色有帮助，但也不能保证工作内容完全相同。

面板至少分开报告：

1. 广告数及职业/企业/角色份额；
2. 在可观测、可处理文本中的明确要求率及未知率；
3. 条件于明确经验条款的年限分布，不能混同所有广告的平均经验门槛；
4. 软件要求与经验/学历要求的联合分布；
5. 可比企业—角色—地区内的变化与广告权重变化，固定权重结果只是一种估计对象。

每个特征比例同时保留总广告数、文本匹配率、可处理数、未提及数、歧义/失败数。未知和未提及不统一填零；若以“明确提及率”为结果，未提及可贡献非提及，但必须明确这不是实际要求率。对无文本/无法处理部分可以给保守范围，不擅自假定随机缺失。

2018—19 可作为候选覆盖较好的前期基准，2016—17 做扩展，最终依实际覆盖和时间审计确定，不能根据经济结果选窗口。疫情/再开放/行业周期单独诊断。2023 起仅是生成式 AI 扩散期划分，暴露 × 时期的回归需要另做识别设计，不能自动称为 AI 因果效应。

Revelio 后续用于同一可比单元的入职者事前经历分布；不建立不存在的广告—个人匹配，不把广告要求与员工构成同向变化当作机制证明。

## 9. 最小交付与执行顺序

| 顺序 | 交付物 | 验收/放行条件 |
|---|---|---|
| 1 | 文本版本与时间字段审计、供应商待确认问题 | 明确哪些时间解释已证实，哪些仅是假设 |
| 2 | JOB_HASH 连接与覆盖审计、冲突台账 | 不扩张广告分母；区分下载缺口与源数据缺失 |
| 3 | 抽样清单、标注手册、变量字典、证据结构 | 研究概念有可复核定义，未提及/歧义可保留 |
| 4 | 小规模语义抽取及独立验证报告 | 达到拟使用指标的预定精度；时间可比性审计通过 |
| 5 | 两地区同版本全量抽取及成功/失败 manifest | 每个原始广告可追溯，重启不重复或丢失 |
| 6 | 招聘结构/要求面板与质量图 | 时间、职业、覆盖、权重及分母口径清晰 |

核心落盘对象：`description_link_audit`、`ad_text_map`、`requirement_features`、`requirement_evidence`、`extraction_validation_report`、随后才是 `hiring_requirements_panel`。这些是拟议交付名，不表示文件已生成。

存储：原文唯一副本保留；紧凑特征与文本级抽取缓存按预算分片，证据只保留必要片段/指针；不另外复制数百 GB 正文。每阶段先测输出大小再决定全量预算，不能沿用索引大小推算语义特征大小。

计算：CPU 并行负责已通过验收的分片任务；GPU 只在确定采用且验证过适合 GPU 的本地模型时才需要。CPU 使用率不是成果指标，应看正确处理的广告数/时间、内存、I/O、失败与可复现性。下载与文本解析是两种瓶颈，不能靠多开文本进程提高外网下载带宽。

分工：主任务负责研究概念、时间解释和验收；较低成本模型负责有限范围实现/字段文档核对；Python/Arrow/DuckDB 做重复全量运算。避免多代理重复解释同一数据或用大模型逐条读取数亿广告。

## 11. 边下载边处理：本次执行决定

### 11.1 JOB_HASH 不能当作正文版本号

重新读取当前数据的 Dewey API 缓存说明 `metadata/job-records-get_dataset_docs.json`：它明确写 JOB_HASH 是 URL 的 MD5，并区分特定地点的 JOB_HASH 与多地点 BASE_HASH。这与“JOB_HASH 由正文计算，正文改动必然换 hash、旧版必然保留”的说法不同。字段叫 hash 本身不能推出其输入是什么，更不能推出供应商的历史保留政策。

我们自行计算的 RAW_SHA256 / NORMALIZED_SHA256 才是当前抽取值的文本指纹。它们可以发现手上两段文字是否相同，不能恢复供应商没有提供的旧正文或生效日期。

采用建议中的按 JOB_HASH 连接与抽样比对；不采用其版本保证及 `CREATED 或 LAST_UPDATED 到 DELETE_DATE = 文本有效期` 的推断。同公司同标题不同 JOB_HASH 可能是不同空缺、地点或重复发布，因此这种 diff 只能做广告相似性诊断，不能验证同一广告的正文版本规则。真正的版本验证需要同一广告身份在多个带日期档案中的变化和供应商规则说明。

### 11.2 昆山：现在进行匹配，不复制全量正文

先复用已验证的 20 个分片索引（2,466,654 行），与全部 269 个 Records 分片匹配。输出广告来源指针、质量字段及匹配的标题、公司、地理、生命周期日期；正文通过 source file + source row 回读。核对键基数、孤立文本、公司冲突、连接行数，以及按广告首次观察期分组的连接结果。日期列始终按供应商观察日期命名，正文版本日期另记未知。

完整 Records 保留为分母；匹配试样可以只落盘 matched 行，但必须同时输出整个 Records 的分母与匹配/未匹配聚合表，不允许将 matched-only 文件当作全样本。描述侧多值必须显式计数并隔离冲突，不能任意挑一个值以伪造一对一。

通过小规模验证后，对昆山当前 1,358 个正式 Description 文件投影读取 JOB_HASH/COMPANY_ID 等必要列，开展现有范围内的全局连接审计。避免为每一个文本分片重复扫描所有 Records，也不写出 300 多 GB 的重复正文。按完整文件清单固定本轮范围，后续新增文件以新批次补入。

当前免费 CPU 队列 kshctest02 用于该任务；不为字符串匹配开启付费资源或要求 GPU。建议 CPU <=8、内存 <=24GB，本轮新增输出和 scratch 合计 <=20GB；实际作业状态和验收结果见后续执行报告。

### 11.3 华中：增量准备，不跨区复制 Records

8 路下载独立继续。处理程序仅领取已完成、大小与校验回执一致的正式 Parquet，不读 .part；排除昆山已有的 1,358 个文件，防止两区重复处理。先验证 2 个文件，再以 4 个低优先级进程处理并等待后续完整文件，每文件原子写入、完成清单、断点续作。

现阶段保存键、来源行、正文指纹和质量状态，供后续抽样、重复缓存与 match 使用；不是学历/经验/技能的语义清洗完成。保持两区相同基础字段和代码版本。不必把 63GB Records 复制回华中，随后只把紧凑处理结果迁入昆山并按文件清单增量连接；需要正文证据时按来源指针读取相应区域原文。

新增基础输出预算 15GiB、空闲预留 10GiB、单文件临时输出上限 128MiB。后台任务不依赖笔记本联网，但关闭服务器仍会中断；进程结束不等于平台停止计费。

### 11.4 哪些结论现在不能发布

目前可以发布本轮文件中的匹配率、冲突数、处理质量和待标注抽样清单；不能把尚未到齐造成的未匹配当成供应商缺失率。完整历史覆盖结论需要全量清单对齐；正文历史要求趋势还需要版本时间解释和语义抽取验证。

## 12. 强制加入后续清洗报告的时间风险诊断

用户明确要求以下问题进入实际计算与交付，而非仅在讨论中提醒。每轮连接完成后执行，新增数据到齐后增量更新或统一复算，保留版本与输入清单。

### 12.1 广告关闭后正文是否固定

状态必须单列：供应商已确认 / 有带日期档案的实证支持 / 未确认。当前单一快照的 Description 没有正文时间戳，不能通过 hash、无 LAST_UPDATED、非空 DELETE_DATE 或某次连接成功认定历史正文被冻结。

保留供应商待确认问题：正文首次还是末次抓取版本；关闭后是否会回写；URL 再出现/重用时旧正文如何处理；LAST_UPDATED 的触发字段与空值含义；是否有可用历史日/月快照。未获得外部联系授权不自动发信。

如后续拿到历史快照，固定同一 JOB_HASH 并同时核查 URL、公司、地点及身份变化，比较关闭前后正文指纹；报告观察到变化和未观察到变化的数量及快照间隔。未观察到变化不等于证明永久冻结。

### 12.2 匹配美国广告的跨期比例

单位是唯一 Records JOB_HASH，主样本沿用 COUNTRY == USA。Description 多值先做键级 membership，不让重复文本行扩张分母；公司冲突、文本非空与可解析状态分别作标记。明示本轮是现有到货文本匹配样本，不是已完成全库样本。

主观察区间：CREATED 到 LAST_CHECKED。替代区间：CREATED 到 DELETE_DATE，仅限日期非空且顺序有效。两者是供应商观察范围，不是确认的连续在架期或正文有效期；可能发生再出现和不可见的间断。

报告完整分母链：匹配美国广告总数、有效主区间数、缺日期数、负区间数、晚于快照数、缺删除日期数、有效替代区间数、公司冲突数。缺删除日期称为未观察到关闭/缺失，不自动断言永久在架。两套区间不把无效值填零或强制互补。

在各自有效区间分母下计算：

- 跨季度：起止时间的日历年—季度不同。
- 跨年：起止年份不同。
- 跨生成式 AI 分期边界：start < boundary 且 end >= boundary；主界线 2022-11-30 00:00 UTC，敏感性界线 2023-01-01 00:00 UTC。这是预先规定的日历分期，不声称为精确采用或外生冲击时间。
- 边界风险同时报告占所有有效区间的比例、占界线之前开始的有效广告的比例；仅报全时期总比例可能稀释前期样本污染。
- 观察跨度的中位数、90/95/99 分位；LAST_UPDATED 缺失、与其他日期顺序异常、跨分期的分布。LAST_UPDATED 不是经验证的正文日期。

按首次观察年/季度分别报告上述比例。避免用“多数广告很短”代替边界跨期的直接计数。

### 12.3 风险是否集中

先按公司、首次观察 cohort、州汇总计数和比例，附各组分母；公司同时报告广告加权总体值、公司等权分布及样本量，防止大公司掩盖小公司差异。展示公司排名时先固定最小有效分母（初版100条）并保留阈值以下合计，不能事后为结论选择阈值。

识别职业集中度需要历史一致的职业映射，现有 Records 无 SOC。此项明确列为待职业映射后交付，不把公司当职业、也不临时凭标题猜测职业。映射通过审计后，按职业族及预先固定的 AI/传统任务暴露组报告同样的计数、分母、跨期比例和覆盖率；未分类单列。

当前不以风险排名或显著性挑选所谓“最关心企业”。若已有事前研究企业组，保留名单、生成规则和时间；否则先交付全体企业分布。

### 12.4 交付和验证

拟交付：`temporal_risk_overall`、`temporal_risk_by_cohort`、`temporal_risk_by_company`、`temporal_risk_by_state`、`description_history_evidence_status`；职业分组标记 pending_mapping。实际格式 Parquet + 小型 JSON/Markdown 摘要。

测试包括：季度/年份恰好边界、跨年同季度编号、起点等于界线、终点等于界线、空日期、负区间、多份描述同键不重复计数；所有分组计数与总量守恒。运算尽量对 Records 必要列做一次扫描并复用匹配键，不复制原文或逐文本分片重扫全 Records。

任何跨期结果只衡量潜在时间归属风险，不等于正文确实被修改的比例，也不证明时间区间内的初版和末版要求相同。

## 入场前仍缺的最小控制

1. **评分绑定的发布mask。** 完成固定独立评分后，以协议/评分/输入框架SHA锁定通过的研究量及其精确依赖；当前集合为空。请求只合并同一上下文兼容且确实缺的合格依赖。每个输出都取“独立通过依赖 ∩ 本次请求缺口 ∩ 本条工程有效字段”作为发布mask，保留未通过项的原状态。不得按整广告、整family或整模块放行；源引文、同条款关系和结果SHA随值保存。跨字段派生需其全部依赖合格，明确未获资格的对象体系、完整B逻辑、个体D路径和历史/因果量仍不可用。
2. **有限新输入和全局排除登记。** 将已消耗的Stage 5窗口及所有新暴露并入现有manifest/排除并集，再从真实后继游标准备首100个；保留accepted/saved/unknown/quarantined/not_reconciled、保护并集和既往prepared成员。领取以完整规范化context SHA作项目级唯一主键，并绑定本次精确依赖集合；事务中检查项目既有领取/暴露，避免跨批、跨进程重复；审核只引用已有试产成员。当前135仅是确认框架，没有已认证的10k试产队列。
3. **试产单一预算及速率入口。** 当前Ledger按leg目录隔离、硬编码150/$50、12RPM及串行；它不是跨并发worker的共享10k/$150账本。最短方式先保留单生产领取进程和模型串行，统一试产计数与预留，跨leg继续等待前一窗口清空，并与现有共享模型锁相容；并发增加前才接共享原子token窗口。Luna80k调度、Kimi不超过项目剩余共享额度、Astra同样受其约束，按实际服务端RPM/TPM向下收紧。
4. **实际入场成本校核。** 首100内记录请求入场预留、实际usage、延迟、429与重试、成功及发布字段数；额度先到即停，不为了满10k加钱。S1的$135.792依赖12k输入假设；当前代码使用请求UTF-8字节上界加1024预留，现固定请求约20–40KB，不能把该情景价当真实硬上界。失败/无usage尝试保留预留，和usage估价不相加；统一核原$450及原步骤3/4分账，基础设施也不当免费。每输入每模型最多2次且物理尝试总数受20%上界及美元更早截止约束。
5. **结果原子落表与恢复。** 复用原适配和QA的来源绑定/未知值约束，新增试产侧car状态而非覆盖旧表；领取、请求、响应、字段mask、证据、SHA和提交标记可恢复对账。保留未完成分母；中断或返回身份不确定时冻结该领取，不盲重发。需补的是mask越权、并发重复、预算耗尽/崩溃恢复等增量控制验证，不重做旧工程测试或旧500资格测试。

最短接续是：固定评分产生合格依赖 → 接好上述mask/唯一领取/统一预留 → 从现队列真实后继游标处理首100 → 依据其实际成本和速率在同一10k/$150范围继续。若无独立合格研究量，试产保持关闭。全局唯一广告/上下文和字段净缺口尚未定，它阻止全量报价和全范围完成声明，但不应迫使一个已证实新鲜、来源明确的有限窗口先做全库扫描。

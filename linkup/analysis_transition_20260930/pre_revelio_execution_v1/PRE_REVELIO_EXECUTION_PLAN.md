## 1. 这一阶段完成什么，完成后停在哪里

研究主线仍是：计算机化与 AI 如何改变不同类型经验的作用，以及以后能否从人员进入和流动中看到对应。现在完成 LinkUp 的可复现测量与需求表述分析、可取得的历史计算机化基准、人工诊断、后续履历接口。Revelio 到位后才检验实际人员经历和流动。

本阶段终点是一个可写进论文方法与描述事实部分的交付包：六张主表、最多三组敏感性、一份最多 40 条的人工复核、一份历史比较基准或明确的资料缺口、一页结论边界，以及代码和来源记录。每项标为 `complete / limited / blocked / unavailable`；没有资料的项目不能伪装完成，但也不让它无限拖住其他结果。

**不在本阶段完成：** 录用概率、实际经验回报、跨职业进入因果效应、AI 对就业的因果效应、完整计算机革命与 AI 革命的同口径因果比较。它们需要现有交付之外的人员/历史/识别信息。不会通过再洗一轮文字弥补这些缺口。

## 3. 时间和计数单位：现在固定，避免以后返工

供应商确认：JOB_HASH 是抓取 URL 的 MD5；同 URL 重发可保留 hash，正文变化会更新关联描述。详见 [供应商证据摘要](VENDOR_TIME_EVIDENCE_20261003.md)。

因此本轮分析单位准确写为 **“交付中经去重的 JOB_HASH/URL 招聘记录及其关联正文”**。正文证据条数、URL 记录数、独立招聘事件数、岗位数、拟招人数、录用人数分别对待，不互相替代。同一 URL 可以承载不同时期的招聘事件；现有一个 hash 不能替我们分出这些事件。

| 可以报告 | 不能由现有数据单独推出 |
|---|---|
| 每年首次观察到多少新 URL/键；对应的交付正文包含什么要求 | 每年新增多少独立招聘事件，或所有当年实际招聘要求 |
| 同公司相近岗位，不同年份首次出现的 URL 所关联正文有何差异 | 差异恰好发生在 CREATED 年份；每个 URL 的旧正文从未被改过 |
| 本次交付保存的正文之间，技术与经验表述怎样共现 | 当前所有企业在同一个现实日期的招聘要求 |
| 有效记录观察区间跨季度、跨年、跨 2022-11-30 / 2023-01-01 的比例 | 实际正文修改比例，或跨 AI 时点的真实要求变化 |

“交付快照”也不等于“2026 年同时在招的岗位横截面”：其中可能有早已关闭的 URL 和不同时间保存的正文。主文统一称“本次交付所保存的要求表述”。CREATED 是首次观察队列，不能当正文生效日。截止交付 2026-09-06，队列的最后完整自然季度是 2026Q2，Q3 单列为部分季度；完整季度不代表无覆盖遗漏。

关闭后是否固定最后正文、本次 Dewey 具体选版、历史日文件是否存档/可取得仍未由邮件回答。本阶段不等待这些答案；不再为此循环询证。若以后取得版本文件，作为另一个有新输入的阶段处理。

### 用户提出的同公司相近岗位逐年对照：现在纳入，不无限扩展

在窄表连接时先形成公司×标准化职位名×地点×首次观察年候选表。只做大小写、空白和标点的确定性标题规范化；同名是比较线索，不保证职责相同。职位族/职业码另列，不用 BASE_HASH 直接代替招聘事件，也不把不同地点合并当同岗。

固定取至多 **20 个至少覆盖三年的公司—岗位—地点组**，以固定种子 20261003 从符合条件组抽取，不按 AI 词、经验变化方向选样。每组每年按稳定哈希次序取至多 3 个键，总原文上限 **200 条**；超过上限按同一稳定顺序截断。全候选组的年度不同键数量只做窄列汇总，不拉全库原文。

私有对照表列出：COMPANY_ID、原始/规范化标题、地点、JOB_HASH、可得 URL、CREATED/LAST_UPDATED/LAST_CHECKED/DELETED、正文来源、独立计算的全文摘要、已有技术/经验候选值。公开 Git 仅保留匿名汇总、方法和无原文的例示结构。

输出四类事实：新键且正文相同；新键且正文不同；仅有一个键而观察跨度很长；字段不足无法判断。全文摘要相同只表示交付正文相同；若同一键只有一份正文，就将“该键是否曾改写”标为不可测，不能算零次修改。**按年出现新 hash 是 URL 更新证据，不是当年正文留存证明。** 不管看起来多整齐，都不自动解锁历史要求回归。

## 4. 冻结测量与两个主比较

继续使用冻结 V6 和现有 enrichment；不再开发解析器，不换大模型重新标全库。四个经验对象：一般工作、职业/任务、行业/领域、工具特定。技术区分传统软件/信息系统、预测型 AI、生成式 AI、泛称 AI；角色区分开发、实施、使用、治理、未知。

### 指标口径

1. 主指标是每个合格 URL 记录是否包含某经验对象的**明确绑定、申请者语境、required 或 preferred** 候选条款。分母为该组所有合格记录，包括未检出者。未检出在计算中是“未检出该指标”，不是“雇主不要求经验”；未知对象、绑定不明、处理失败另列。
2. 年限只统计明确数值—单位—经验对象绑定的条款；单列最低、最高、区间和不等式。不把“缺失”补零，不将范围上限当最低要求，也不取整篇广告最小数字代表门槛。展示下界区间：明确 0、(0,1)、[1,3)、[3,5)、≥5；缺失、无法绑定、无可解释下界单列。不同对象不合并成年限总数。
3. 技术、角色、经验是多标签。一个键可进入多个对象行，比例不需要加总为 100%。现有 technology×experience 表包含广告内候选组合，**只叫共现，不能叫某技术要求某经验**；两者各自 explicit 也不代表技术与经验之间存在直接关系。
4. 学历、明确无经验、资格替代仍是 audit-only。工资、全兼职、remote 本轮只给覆盖/时点说明：先前全 Records 匹配约 10.78%、28.56%，remote 时间集中于 2024；不自动作全样本控制变量，更不称技能工资溢价。

### 只做两个主比较，不按结果追加题目

| 比较 | A 组 | B 组 | 解释 |
|---|---|---|---|
| C1 使用角色，主结果 | 有明确生成式 AI 使用候选；可同时提传统软件 | 有明确传统软件使用候选，未检出任何 AI 技术类别 | 相近职业和角色中的交付要求表述差异 |
| C2 开发角色，次结果 | 有明确生成式 AI 开发候选；可同时提传统软件 | 有明确传统软件开发候选，未检出任何 AI 技术类别 | 避免把 AI 开发与软件普通使用混在一起 |

“未检出 AI”不是未采用 AI。预测型/泛称 AI 单独报告覆盖，不临时扩大为 any-AI 来救一个稀疏的 GenAI 比较。实施、治理及未明确角色出覆盖表，本轮不增设主比较。不能称传统软件组已经证明是“成熟阶段”；角色控制只能部分减少扩散阶段构成差异，不能消除它。

两个比较均报告全部四种经验对象的比例差及原始计数，不选显著性最好的对象讲故事。合格总体限定为可用正文、美国匹配、有效首次观察日在 2018-01-01 至 2026-06-30 的冻结记录；这是队列选择，不是正文所属时期。2016–17 扩展另列；其他日期、缺失和 2026Q3 在全库漏斗/覆盖中保留。

共同样本按**已核验职业大类×美国 Census 大区×首次观察年**划格。未知职业/地区只进覆盖表；主比较只使用可分类且两组均有至少 20 条记录的格。每组总数至少 200；共同支持需覆盖至少 5 个职业大类。以上是事前选定的可读性/支持规则，不是统计定理。每组保留比例逐项报告；低于 70% 时结果只能描述重叠子样本，不能推广到整组。C1 或 C2 不满足支持就取消该比较，不拖住另一个。

标准化权重固定为两组共同支持格合并后的记录分布 q(x)，两组用同一个 q。每个经验对象报告：原始比例差、标准化比例差、两者之差及保留比例。它是可观察构成调整，不是技术因果效应，也不是把“同类职业”当“完全相同任务”。企业身份先用于覆盖与集中度；同企业限制只做敏感性。

不为这个选择性数据库制造人口抽样推断。本轮主报告给分子/分母、百分点差、职业分布范围及企业集中度；不以 p 值决定结果是否值得保留。CPS 的抽样误差按其核验后的调查设计另行处理。

### CPS 与计算机化：保留比较目标，独立证据桥接

一次清点实际 CPS 的年份、样本、职业版本、权重、工作计算机使用补充问卷、工资字段及可用 crosswalk。检查现有项目是否已经冻结历史 routine-task-intensity 指标；**不得假定已拥有或自动使用现代 O*NET 回填历史技能。**

- 若有足够早且可比的年份、权重和历史任务映射：在实际共同覆盖范围中，最早和最晚各取不重叠的三年窗口；不足以各取三年则报告实际可用窗口，不伪造年份。报告就业职业/任务构成变化，任务分组界点按首期权重固定，列无法映射比例。
- 若只有近年：同样形成近年就业结构基准，明确不叫“计算机革命结果”。历史背景可引用已有核心文献/官方表，不能冒充本项目复现。
- 只有在补充问卷中实际存在可比较的 workplace computer-use 字段时，才输出工作中计算机使用比例。官方说明 CPS 自 1984 年起不定期有计算机/互联网补充调查，并不意味着每期都有相同的工作用途问题。[Census 说明](https://www.census.gov/topics/population/computer-internet/about.html)

无 CPS 文件访问或关键映射时，交 `CPS_INPUT_GAPS` 和可执行规格，状态 unavailable；不为找更多数据重开无限综述。

## 6. 人工复核：40 条以内，错误影响结论，而不是触发重洗

从锁定样本中按技术角色/常见经验类型分层抽 32 条核心样本，再取至多 8 条预先定义的绑定、否定、区间年限难例。固定种子 20261003，保存抽样概率/层总量；排除既有 heldout-400。难例不与核心样本混算总体准确率。模型标签隐藏，用户/助理先读原文独立填表，再揭示预测。

至少 8 条核心样本安排两名人类复核；如果实际上只有一名复核者，照实记录，不用模型冒充第二人。只做一次冲突裁决。不得为得到好看的准确率换样本。

报告返回数、分对象误判计数、无法判断、冲突，以及抽样范围。40 条只能诊断常见问题，不能证明稀有类别和全库的高精度。没有足够例证的类别仍标 candidate；若发现可重复的语义错类，降级该维度或移至附录，本轮不全库重解析。不用“工程准确率 99%”替代语义诊断。

L5先交三项：四类要求及一般年限的分布/联合分布；在明确一般年限相近的记录中比较相关经历要求；比较岗位构成与更细工作条件下的差异。第二项只对披露可比年限的子样本成立，不把工具或行业年限当总年限，不把条件关联叫技术总效应。

旧C1的原始权重保留为旧新测量的共同基准：`W_h=(N_Ah+N_Bh)/sum_h(N_Ah+N_Bh)`，各格分别用抽样权重估计两臂均值，再用W_h加权差值。不能直接用抽后3:1比例、也不能因两库50/50就把两技术组权重改成50/50。原软件臂在合并人口中占约99%，这一目标人口应显式说明。

新版经角色确认的比较需要重新报告可分类人数和共同支持；按照事前同一支持规则执行一次，不能假设仍有10,075条或69格。新确认组只能代表旧两臂抽样框内可重新分类的群体，不能恢复框外全部AI/软件岗位；改变组别的记录仍使用其原抽样层的入样概率。600条诊断另列，不拼成新的全库总体。旧组/旧W的重测结果与新确认组结果分开；丢失的共同格权重占比另列，权重重归一化对应新的有支持子总体，不再声称原总体估计量完全不变。

细职业与公司分析冻结一个规格：公司主体×细职业具有两臂支持，再在可识别单元内比较；若支持不足，报告有限结果或取消该规格。仅筛进“两类广告都出现过的公司”不叫公司内比较。相近工作不要求所有广告逐条匹配，也不把公司/职业固定效应理解为消除采用选择。

置信区间若报告，采用设计权重、公司层聚类并说明只反映相应抽样/组内相关不确定性，不覆盖模型测量误差和选择偏差。职业固定效应吸收职业层不变的beta，故职业beta梯度与同职业内部AI提及比较分开。技术证据句与经验句重叠及删除重叠后的结果只作预定诊断，不据此称耦合已消除。

### 11.5 Revelio：独立的半篇实证模块

**R0最小入口。** 不要求先把约1TB全上传。先取得实际文件位置/清单、字段和表关系，再按稳定person ID取约10,000人的全部可见任职史作为工程输入，并取对应公司/职业映射。抽person而非职位行；选择有美国职位者时仍保留其美国以外的既往经历。样本必须从明确的人员框抽取，不能只从成功转职者抽取。若源端尚无法读文件，这一任务标明缺少的具体入口，不能假装可执行。R0是Revelio生产的正式入口门槛：人员框、完整career与关键字段未通过前，不启动R1实证运行，也不承诺该半篇按日历日期完成。

**R1事前经历。** 只累计事件发生前的已观察任职区间，区间取并集，避免兼职重叠重复计时；实习单列，月度同月顺序不明保留标记，左侧缺失不是零经验。分别构造观察到的总工作时长、同目标职业、同行业及固定O*NET内容相近职业的既往时长/是否出现。职业内容相似是代理，不是个人技能认证。不依赖岗位正文构造工具经历。若只有当前公司行业标签，则明确采用固定分类代理，不能声称历史行业归属已获逐期核验；行业未知单列。

**R2第一张核心表。** 入职事件用三个轴编码：内部/跨雇主；首次观察/已有可见工作史；对目标职业首次进入/返回/连续。每个轴内部互斥，轴间可交叉，避免把“首次目标职业”和“跨雇主”错误当成互斥通道。报告进入者在相同观察总资历下的相关经历分布，附历史可见程度和映射覆盖。首次观察工作不能自动叫真正第一次就业。

**R3第二张核心表。** 在实际资料支持时，以期初可观察在职人员形成风险集，固定12个月窗口报告观察到的目的职业转入率，辅以来源—目标相关经历。不能用成功转职者作分母；无更新或失访不是自动未转职。若不能区分持续观察与失访，主结果改为有明确分母说明的记录进入构成，不把它改名为转入率。此分支只裁决一次，不无限搭建毕业生总体或申请人数据。

R2/R3按独立冻结的职业技术暴露与任务框架抽取/分层，不限制在LinkUp的10,075条AI候选对应雇主。扩大样本按事先计划的人数/窗口、存储及覆盖决定，不看显著性才决定扩样。主工程由Python/SQL完成，不让大模型逐个阅读百万人的履历。

### 11.6 两库连接与历史比较

J1形成共同职业和雇主样本框，记录不同公司主体、子公司/母公司映射和未匹配情况。各库先报告全体可用人群，再报告共同支持群体，不能通过只展示交集掩盖代表性下降。

没有正文版本日期时，只做职业/公司/地区等群体结构对照，明确LinkUp是混合保存时间的文本、Revelio是有日期的职位事件。禁止把CREATED季度的文本要求与同季度入职者解释为同时需求和录用，也不伪造广告—人员一对一招聘匹配。代码输出合同直接禁止在J1生成跨库季度匹配键或“同期要求”字段；CREATED年只作首次观察队列/抽样层。不能从两侧比例差异直接推断筛选、供给或雇主偏好。

G1在一天以内核验现有计算机化指标、AI beta及任务定义在可用年份/职业分类上的共同含义。只查会改变这个裁定的最多3个具体文献/官方数据问题，给采用/限制/不可执行的明确结果。Revelio的前AI年份是前期比较，除非有独立技术变化度量，不能叫计算机化冲击。正文版本答复可作为补充，最多整理一份给用户转交的问题，不未经授权联系供应商；不放在主生产关键路径上。

### 11.8 成本与集群执行预算

编写代码的agent与批量推断服务分开。Codex可调模型不等于已有可调用、已授权付费的批量API；开工先实测200条的平均输入/输出、耗时和失败，并确认合法调用通道与预算，不假装批量调用已获保证。示例：4万条若平均2,000输入token、400输出token，则约8,000万输入和1,600万输出token，尚未计盲审和推理；这不是本项目实测账单。

开发批比较后冻结最轻且满足证据/schema要求的配置。默认批量候选Terra/medium；若关键对象或角色持续不合格，升级Sol/medium一次，随后冻结。若成本不合适，在读取新经济结果前，一次性缩小正式随机样本并重算入样概率，而不是跑到显著就停。新样本不必全纳10,075条A，若预算裁定改为抽A，必须记录相应pi_A并更新目标说明。批量开始前必须记录真实batch入口、数据许可范围允许该处理方式、实际模型标识/版本/参数、预算上限和开发批成本回执；不推测用户订阅已经覆盖这些调用。没有通道时，L1/L2代码/定义可交付，L3明确未启动，不用对话窗口硬吞四万篇正文。

正文逐字相同可缓存一次提取，但仍按每个URL记录计数，不能悄悄改为唯一文本总体。同一文本跨开发/评价的泄漏要按文本摘要分组排除并记录受限评价人口。输出逐条保存证据；机器可验的JSON、证据偏移、日期和区间先用代码检查，不让GPT-6重复数数。

集群按数据所在地分片，产出窄表合并；不重复搬运或重洗全库。CPU文本读写和区间运算先用实际吞吐量选择16/32核任务及匹配内存；没有适配的推理运行时不为CPU脚本占用DCU卡，GPU计算单元不是CPU核。若用远程API，CPU只做I/O，不能用CPU占用率判断模型推断效率。存储/申请资源仍遵守用户现有额度和授权，不因为规划需要就自动开新付费服务。

本轮只有三个GPT-6集中决策点：定义/估计对象；开发批后的配置与可测性；最终结果与主张。未知问题由执行agent合并成一页，先查实际字段，再由GPT-6作有期限的资料核验或明确裁定。只有新证据推翻既有条件才重开决定，不把“可能更好”当重跑理由。

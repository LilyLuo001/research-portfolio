# C1/C2 comparison join runbook

`build_comparison_join.py` consumes the complete semantic-narrow batch, the complete hash-partitioned Records index, the delivered snapshot O*NET table, and the official 2019 O*NET code list. Production requires an exact complete 2,464-shard batch receipt. The one-shard validation mode is accepted only with `--expected-shards 1` and an actual semantic-narrow receipt whose `canonical_ads` equals the Parquet footer row count; its output is a pilot and is not a library estimate.

The canonical namespace is `JOB_HASH + SOURCE_FILE + SOURCE_ROW + RECORD_SOURCE_ROW`. `JOB_HASH` must be 32 lowercase hexadecimal characters, `SOURCE_FILE` must be a basename, and both row fields must be nonnegative. The program first writes all `JOB_HASH` values into 16 lowercase-hex prefix partitions and computes global counts after grouping within each partition. Because the narrow input has no trusted full-text digest, every occurrence of any repeated `JOB_HASH` is excluded from the comparison input and counted in `GLOBAL_JOB_HASH_AUDIT.json`. Duplicate keys remain private.

Only rows with at least one explicit generative-AI or traditional-software use/develop flag proceed to the linkage step. O*NET is scanned once to build a candidate-key projection. Each active prefix then joins only its matching Records partition on `JOB_HASH + RECORD_SOURCE_ROW` and its O*NET projection on `JOB_HASH`. Any one-to-many match or disagreement between narrow and Records `CREATED` dates blocks publication. Missing Records, occupation, region, company, and date fields remain missing and are counted; no row is invented or expanded.

The joined files retain the canonical keys and source locator, the semantic flags, Records `CREATED` and `COMPANY_ID`, official occupation major, Census region, and the frozen observation-risk fields. `COMPANY_ID` means company-scrape subject, not verified legal firm or consolidated group. Occupation is the current delivered snapshot mapping, not historical occupation evidence. Dates are delivery observation metadata, not text-effective dates.

`build_fixed_comparisons.py` reads all verified joined prefix files together. Common-support cells, pooled weights, arm totals, and thresholds are computed globally after the merge; no prefix makes a final support decision. It writes `FIXED_COMPARISONS.csv`, `T5_MAIN_COMPARABLE_EXPERIENCE_CONTRASTS.csv`, `T6_SENSITIVITY_AND_CLAIM_STATUS.csv`, and a hash-bound receipt. The production command is `sbatch run_comparison_join_ks.sbatch`; the approved real-data validation command is `sbatch run_comparison_join_pilot_ks.sbatch`.

## 目前学到了什么，仍不能说什么

首轮结果已经把“数据连接是否能用”和“研究变量是否成熟”分开。前者具备可追溯的全库行数与文件核验；后者仍需实际原文复核。现有美国可用记录中的明确一般经验对象检出约 0.52%、领域经验 4.69%、列入词典的工具经验 1.02%，未分类经验对象 27.61%。这些类别可重叠，不应加总；它们衡量现有规则明确识别到的表达，不是各类真实要求的完整普及率。

技术侧明确使用角色的生成式 AI 候选为 12,431 条，明确开发为 872 条；对应传统软件候选为 5,991,051 和 13,682 条。这只是全库冻结规则的候选规模，尚未施加 C1/C2 的年份与共同支持条件；全局键去重审计已通过。尤其开发侧，不能先看原始均值再决定比较口径。

因此，这轮可以推进保存文本的经验组合描述及有限同类岗位比较；目前不能据此回答 AI 是否降低真实技能门槛、是否改变录用概率，或相对于历史计算机化产生了因果上不同的结果。下一项实质证据是已冻结的支持检查与原文人工诊断，而不是增加更多回归或扩大解释。

## 本轮解释边界

1. 官方确认 JOB_HASH 是 URL 的 MD5；同 URL 正文修改可保留同一 hash。CREATED 是首次观察日期，不是当前正文的生效日期。年度同类岗位出现不同 hash 只能证明存在不同 URL/广告对象，不能独自证明正文保留了当年的版本。
2. 时间风险主区间为 CREATED 至 LAST_CHECKED。DELETE_DATE 表示观察到广告消失；异常顺序、缺失和跨期分别报告。三日期同季度的已关闭广告仅是限制样本，不是历史正文未改写的证明。
3. COMPANY_ID 对应抓取公司主体，未自动等同于法律企业或企业集团。职业为当前交付的 O*NET 映射，不假设历史不变。
4. C1 比较生成式 AI 使用与未检出任何 AI 的传统软件使用岗位；C2 比较相应开发岗位。固定共同支持和标准化权重，不因结果稀疏而换定义。结果只描述保存文本中的要求组合，不识别技术扩散的因果效应或录用概率。
5. 人工盲包从全库可用窄表、排除全局重复 hash 后抽取，不只从技术候选组抽取。原 heldout-400 键清单未找到，按 D18 排除可核验的既往复核案例并明确这一限制；本轮是有限人工诊断，不称独立留出集准确率。未收到真人标注前不称人工验收通过。

## Migration and removal

1. Stop conversation-based production readers/auditors and local analytical execution.
2. Transfer active inputs, frozen schemas, code, raw outputs, decisions and receipts into a separate versioned cloud archive. Preserve relative paths and file provenance; exclude credentials, model weights not needed for archival, and unrelated original attachments.
3. Verify destination file checksums and complete a scheduled integrity job. A successful transfer alone is not reported as model production.
4. Only after verified remote preservation, remove the explicitly inventoried active local private-data working directories and generated caches. Do not delete original user attachments, repository history, or unverified unique files.
5. Record the archive path, verified manifest, actual deletion list and released code commit. Retain public code and methods in Git; private text and labels must not be committed.

## Minimum job receipt

Every new job report must include purpose (migration verification, runtime probe, inference or analysis), job ID, submission time, queue/account, CPUs, requested accelerators and memory, time limit, actual observed state, code version/hash, model and runtime versions where applicable, input manifest/hash, output paths and exit status. Requested resources and observed accelerator use are separate facts.

Do not describe a submitted or queued job as completed. Do not describe a hardware probe or archive verification job as a production inference job. Do not call agreement or schema validity accuracy. Existing unknown labels, rejected evidence and time-interpretation limitations remain preserved.

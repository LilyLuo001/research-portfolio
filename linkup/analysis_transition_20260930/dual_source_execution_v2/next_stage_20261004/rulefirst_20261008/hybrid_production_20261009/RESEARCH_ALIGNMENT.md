# D54：代码候选＋有限 Pro 决策审查，保留完整正文的研究价值

2026-10-09 用户选择代码候选加有限 Pro 决策审查。D53 中「Astra全样本联合判读」以及随后讨论的中档 API 批量判读均已被最新决定取代；既有标准化正文、7635唯一文本、10000条样本映射、规则候选、schema、证据和运行记录保留。本路线不称为已校准的中档模型生产。

## 研究对象和购买description的理由

核心是雇主明确要求的经验、资格条件与岗位责任的组合，以及这些内容与技术要求如何共现。它保留了原 employer-side block 区分招聘数量与岗位内容/要求的目的，并服务于计算机化与AI的共同经验测量框架。年龄或title不是entry-level的替代真值；现有数据也不支持用招聘广告直接推断实际录用偏好。

| 核心维度 | 本轮可操作定义 | 代码与模型分工 | 可解释范围 |
|---|---|---|---|
| 经验门槛与进入资格 | 数值年限、一般/职业任务/行业领域/工具经验、必需或优先、明确欢迎毕业生或接受无经验 | 代码定位数字与原文；root在有限开发例中裁决可推广的修饰关系和申请者对象 | 雇主明示条件；未提到不等于没有要求 |
| 资格替代 | 学历或经验、不同经历之间的OR/AND条件及分支 | 代码保留条件候选；root只把开发例中可推广的关系写成版本化规则，复杂条件保持未知 | 明示进入路径；不等同实际进入概率 |
| 岗位责任与seniority内容 | 独立判断/验证、客户责任、管理监督、培训指导、执行任务 | 代码产生候选与证据模板；有限审查区分正文主体后再冻结规则 | 任务责任组合；独立工作不自动定义为senior岗位 |
| 技术内容 | 软件系统、预测型AI、生成式AI；开发/实施/使用 | 字典产生候选；有限审查决定哪些语法关系能够由代码推广 | 文本明确提及；不当成真实采用率 |
| 薪资、学历、职业、remote等已有字段 | 已有结构化信息、来源与缺失 | 优先复用和核验，不新增重复模型提取 | 分层与支持性变量；未知供应商字段能力不强行假定 |

目前JOINT_SCHEMA负责正文核心维度，不声称已覆盖全部学历、薪资、许可或培训政策提取。培训/指导字段区分「员工负责培训别人」与「雇主给申请者培训」；后者没有专门字段时保留原文待后续明确，不混用为一种任务。

## 与Revelio posting的关系

差异首先是测量控制与可审计的条件/责任关系，不是认定Revelio一定没有这些字段。实际字段覆盖尚需产品版本核验；本轮不以购买或上传Revelio Individual为前置条件。供应商已有可靠字段可以利用，原文证据和统一定义仍由本项目保留。

## 不改变的时间和样本边界

LinkUp确认job_hash来自URL的MD5，同URL更新可替换对应description。不同年份有不同hash不自动证明每份文字在首次观察时已经存在。当前样本的created年份为2023–2026，只能把它作为关联的首次观察队列。比较岗位要求的历史变化/任务被删除，需要相应历史文字依据；语义模型不能补出未保存版本。

因此本轮产出是经验—任务—技术的可审计测量与样本内比较，不把当前快照写成已经识别AI造成seniorization，也不宣称已完成计算机革命与AI的历史因果比较。

## 实施与停止规则

- Root Pro 决策审查：每轮最多24篇开发文档，只形成可推广的版本化规则决策；不全量标注。当前19篇候选包中仅4篇全文和1篇部分内容已审阅，不能记作19篇均已审阅。
- 工程代码与 BU CPU：生成候选、证据模板、失败回执、固定诊断与批处理；所有研究数据处理仍在调度作业中执行。
- 无 API、无代理 API、无额外推理账单；不把 Pro 订阅内的有限决策审查包装成 API 或批量语义生产。本轮已有 BU CPU 调度资源使用，不能写成“所有计算零消耗”。
- 独立代码审查抽查已通过、未命中与未知记录，不能只审查规则命中项。
- Luna/low：公共Git、来源和运行记录。
- 开发决策冻结后只运行一次固定诊断；开发例只来自dev120，不使用eval80反复调规则。诊断通过的字段才进入批处理，失败字段保留未知或停止。
- 按变量验收：证据、对象、强度、条件关系分别判断。某字段失败，不强制给标签，不使全部合格字段停工；保留该字段未知率和分组覆盖，不能把遗漏当随机。
- 如使用降级后的变量口径，另存明确版本并限制结论，不以改名掩盖原要求未达到。
- 代码引文核验仅检查一致性，不构成语义准确性证明。AI复核是诊断性参考，不称人工金标准。
- 先前的中档 API 提案已被用户明确取消。本路线不需要 API 密钥或 API 预算，也不得发起付费模型调用。
